# منصة أزل سوفت — المقترح والأثر والمخرجات والنظام المالي

*إدارة مرفق مياه لشبكات الآبار الأهلية · مديرية الرضمة، محافظة إب، اليمن*

---

## 1. الملخص التنفيذي

«أزل سوفت» نظام لإدارة مرافق المياه في شبكات الآبار الصغيرة التي تديرها المجتمعات المحلية. يستبدل الدفاتر الورقية والجداول المتفرقة بسجل واحد لكل مشترك، وكل قراءة عداد، وكل دورة، وكل ريال يتحرّك. المرحلة التجريبية تغطي **10 آبار و60 مشتركًا** في **مديرية الرضمة، محافظة إب**، وتديرها لجان الآبار المحلية تحت إشراف المجلس المحلي للمديرية.

المنصة مبنية وتعمل فعليًا: تطبيق Flutter للأندرويد والويب، وقاعدة بيانات Firebase، وواجهة عربية من اليمين إلى اليسار، وطبقة محاسبية مزدوجة القيد مشتقة من البيانات التشغيلية. النظام المالي ليس وحدة منفصلة تُضاف في النهاية — بل تُرحَّل الفواتير والتحصيلات وتكاليف الآبار إلى دليل حسابات، وتُقرأ كشجرة محاسبية واحدة لكل بئر أو مجمّعة لكل الآبار.

## 2. المشكلة

| # | المشكلة | الأثر |
|---|---|---|
| 1 | الاستهلاك يُسجَّل على الورق لكل دورة | فقدان السجلات، أخطاء إعادة الكتابة، وتعذّر إعادة بناء دورة سابقة |
| 2 | لا يوجد سجل موثوق لذمم المشتركين | نزاعات «دفعت سابقًا» لا تُحلّ بدليل |
| 3 | الفوترة بالتقدير لا بالعداد | تسرّب في الإيرادات واستهلاك غير مرئي |
| 4 | تكاليف تشغيل البئر (وقود، عامل، صيانة) غير متتبَّعة | لا أحد يعرف هل يغطي البئر تكلفته |
| 5 | تقارير اللجان إلى المجلس شفهية | المديرية لا تستطيع التخطيط ولا المقارنة ولا تبرير التعرفة |
| 6 | لا سجل موحّد للآبار والقرى والمشتركين | تكرار المشتركين بين الآبار، ولا رؤية على مستوى المديرية |

## 3. الحل

منصة واحدة بثلاث طبقات:

| الطبقة | ما تفعله |
|---|---|
| **التشغيلية** | الآبار والقرى والمشتركون وقراءات العدادات لكل دورة والاستهلاك بالمتر المكعب |
| **المالية** | حسابات المشتركين، وصناديق الآبار، ومستحقات العاملين، والمصروفات، والسندات، والفواتير، والذمم |
| **التحليلية** | تقارير الدورات، وتقارير الحسابات (يومي/شهري/سنوي)، وربحية كل بئر، والشجرة المحاسبية المجمّعة، ولوحة المديرية |

دورة العمل داخل التطبيق:

```
فتح دورة → قراءات العدادات → الاستهلاك (م³) → تحميل المبلغ على حساب المشترك
         → سند قبض / سند صرف → إغلاق الدورة → التقارير
```

كل خطوة تُكتب في قاعدة البيانات نفسها، فالتقرير ليس إعادة إدخال أرقام — بل قراءة لما حدث فعلًا.

## 5. النظام المالي

### 5.1 النموذج

**دفتر قيد مزدوج لكل بئر** مع تجميع على مستوى المديرية. كل بئر وحدة محاسبية مستقلة، والمديرية مستوى التجميع. فوترة المشتركين والتحصيل تحدث داخل وحدة البئر، فيمكن الحكم على نتيجة البئر دون توزيعات يدوية.

### 5.2 دليل الحسابات

| الكود | الحساب | مصدر الرقم |
|---|---|---|
| **1000** | **الأصول** | |
| 1100 | النقد والأرصدة | |
| 1101 | صندوق البئر | حسابات نوعها cash |
| 1200 | الذمم المدينة | |
| 1201 | ذمم المشتركين | حسابات تحمل customerId |
| 1900 | حسابات غير مصنّفة | نوع غير معروف — لا تُسقَط أبدًا، بل تُعلَّم |
| **2000** | **الخصوم** | |
| 2100 | مستحقات العاملين | |

| **3000** | **حقوق الملكية** | |

| 5101 | وقود وعامل وصيانة | حسابات نوعها expenses |

### 5.3 قواعد الترحيل

- تُقرأ صيغتا القيد الموجودتان في البيانات: القيد على حساب واحد (accountId + debit/credit + نوع الحركة)، والقيد المزدوج الصريح (debitAccountId / creditAccountId + المبلغ).
- تُزال تكرارات القيود بمعرّف الوثيقة، فلا يُحتسب الريال نفسه مرتين.
- يجب أن يوجد مدين ودائن لكل حدث مالي، ويُظهر التقرير الفرق عند غيابه.
- الحسابات التي تحمل رصيدًا مخزّنًا بلا قيود تُعرض برصيدها مع تحذير صريح — لا تُسقَط الأرقام القديمة صامتة.
- كل ما لا يمكن تصنيفه يذهب إلى **1900 حسابات غير مصنّفة** ويُعَدّ ويُبلَّغ عنه، لا يُخفى.

### 5.4 الضوابط

| الضابط | القاعدة |
|---|---|
| ميزان المراجعة | مجموع المدين = مجموع الدائن، ويُعرض في تذييل الشجرة |
| المعادلة المحاسبية | الأصول − الخصوم = الإيرادات − المصروفات، تُعرض «متوازنة / غير متوازنة» مع الفرق بالضبط |
| الاكتمال | الحسابات غير المصنّفة والقيود غير المنسوبة تُعَدّ وتُبلَّغ |
| سلامة الفترة | كل الفترات / هذه السنة / هذا الشهر، مع استبعاد القيود خارج النافذة والاحتفاظ بغير المؤرَّخة |
| الشفافية | تصدير الشجرة كاملة بصيغة CSV بضغطة واحدة للمراجعين والمانحين |

### 5.5 مخرجات التقارير

| التقرير | السؤال الذي يجيب عنه |
|---|---|
| تقرير الدورة (يومي/شهري/سنوي) | كم مياه تحرّكت، ومن استهلكها |
| تقرير الحساب (يومي/شهري/سنوي) | ماذا استلم كل حساب وماذا دفع |
| الشجرة المحاسبية (لكل بئر / لكل الآبار) | ماذا يملك البئر وماذا عليه وماذا كسب وأنفق |
| تقرير استهلاك الطاقة | كم وقودًا وكهرباءً دخلت في كل متر مكعب |
| الفواتير والسندات | الأثر الورقي خلف كل رقم |
| لوحة المديرية | أي الآبار سليمة وأيها يحتاج تدخلًا |

## 6. الأثر

### 6.1 قبل وبعد

| البُعد | قبل | بعد |
|---|---|---|
| تسجيل القراءات | ورق، مفقود، غير قابل للتحقق | رقمي، بختم زمني، لكل عداد |
| رصيد المشترك | ادعاء شفهي | دفتر برصيد جارٍ وفاتورة |
| تسرّب الإيرادات | مجهول وغير محدود | استهلاك بالعداد وذمم مرئية لكل مشترك |
| الوعي بتكلفة البئر | معدوم | تكلفة المتر المكعب ونتيجة كل بئر عند الطلب |
| إغلاق الدورة | عشوائي | فتح وإغلاق صريح مع تقرير عند الإغلاق |
| التقرير إلى المجلس | شفهي | كشوف مصدَّرة يفهمها غير المتخصص |
| التدقيق | مستحيل | كل رقم قابل للتتبع إلى قيده |

### 6.2 من يستفيد

- **لجان الآبار** — تعرف نقدها، ومن عليه دين، وكم تكلّف البئر فعلًا.
- **المشتركون** — إيصال ورصيد مقروء بدل نزاع.
- **المجلس المحلي** — بيانات قابلة للمقارنة ومبنية على دليل لعشرة آبار، ونموذج قابل للتكرار في المديرية.
- **المانحون والبرامج** — سجلات استهلاك ومالية قابلة للتحقق بدل أرقام مُبلَّغة ذاتيًا.

### 6.3 مسار التوسّع

| المستوى | الآبار | المشتركون | الأساس |
|---|---|---|---|
| تجريبي | 10 | 60 | هذا المقترح |
| المديرية | — | ~15,000 | التوسّع في الرضمة |
| المحافظة | — | ~45,000 | التوسّع في إب |

اقتصاديات الوحدة المستخدمة في العرض: **1,500 دولار مقابل 720 قراءة**، أي نحو **2.08 دولار للقراءة** في نطاق المرحلة التجريبية. وهذا افتراض تخطيطي يُؤكَّد مقابل التكلفة التشغيلية الفعلية.

## 9. المخاطر والمعالجات

| الخطر | المعالجة |
|---|---|
| ضعف أو انقطاع الاتصال | تخزين أصول الويب بعد أول تحميل؛ والمحاسبة مشتقة من بيانات مخزّنة، فلا تبعية حيّة للتقارير |
| اختلاط نقص البيانات بضعف الأداء | النظام يسمّي القياس الناقص «غير مقيس» ولا يسمّيه فشلًا |
| سجلات قديمة بلا أنواع حسابات | سلة «غير مصنّفة» مع تحذيرات صريحة، فلا يختفي شيء صامتًا |
| التعرفة غير معتمدة رسميًا | بند مفتوح: النظام يسجّل المبالغ المفوترة، وقرار التعرفة يبقى للمجلس |
| تكلفة الأجهزة على اللجان | جهاز أندرويد واحد مشترك لكل بئر يكفي؛ ونسخة الويب للمراجعة على الحاسب |
| الثقة بنظام جديد | تصدير CSV لكل تقرير، فتتحقق اللجنة خارج التطبيق |

## 10. بنود مفتوحة

1. التعرفة الرسمية للمتر المكعب ولكل نوع استخدام.
2. العدد الرسمي للمشتركين في كل بئر، لمطابقته بالسجل.
3. من يوقّع إغلاق الدورة، وما الوثيقة التي توثّقه.
4. هل تنضم لجان الآبار إلى هيكل فرع إب.
5. تأكيد تكلفة الوحدة للقراءة.
